### 完成

- 新增 `scripts/windows/start-ollama-cpu.bat`：手动以 CPU 模式启动 Ollama
- 新增 `scripts/windows/start-ollama-app-cpu.vbs` + 替换开机自启项（原 Ollama.lnk 备份为 Ollama.lnk.gpu-backup）：开机自启的 Ollama 也走 CPU 模式，托盘功能保留
- 后端按 provider 调整 LLM 并发：Ollama 本地 2 并发（CPU 推理高并发互相拖慢），DeepSeek 云端保持 12

### 问题与解决
- **LLM 模式一直「生成中」**：根因是 Ollama 0.32.14 的 llama-server 在 RTX 4060 Laptop 上 CUDA 初始化崩溃（0xc0000409 + "CUDA error: shared object initialization failed"，GitHub issue #17627 同款，未修复）。每次 LLM 请求 500 → 后端重试 → 全失败 → 降级要素池，期间前端一直 loading。
- **排查过程**：OLLAMA_NUM_GPU=0 无效（llama-server 二进制内嵌 CUDA 初始化）；cuda_v12/v13 后端均崩；清理 PATH 无效；更新 VC++ Runtime 14.51 无效（#17375 的方案针对的是不同错误码）；替换捆绑 DLL 无效；禁用 CUDA backend 目录无效（CUDA 内嵌于 llama-server.exe）。
- **最终方案**：`CUDA_VISIBLE_DEVICES=-1`（注意：空字符串会被 Ollama 环境传递机制丢弃，必须用 -1）强制 llama-server 跳过 CUDA backend，纯 CPU 推理。已验证稳定可用，且只影响 Ollama 进程树，不影响 PyTorch 等其他 GPU 程序。
- **速度实测**：Qwen3-8B Q5_K_M 纯 CPU 约 7 tok/s（16 线程），Vulkan backend 同为 7 tok/s（ggml Vulkan 实现尚不成熟）。生成 1 条约 20-30s（含模型加载），5 条一批约 5 分钟。大批量建议用 DeepSeek 云端。
